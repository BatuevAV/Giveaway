# 🐛 Исправление: Ошибка "There is no text in the message to edit"

## Проблема

При просмотре розыгрышей с картинкой возникала ошибка:
```
telegram.error.BadRequest: There is no text in the message to edit
```

### Причина

Когда бот показывает детали розыгрыша через `view_giveaway_callback`, он проверяет наличие картинки:
- **Если есть картинка**: удаляет старое сообщение и отправляет `send_photo()` с caption и кнопками
- **Если нет картинки**: редактирует текущее сообщение с помощью `edit_message_text()`

Проблема возникала, когда пользователь нажимал на кнопки (например, "Опубликовать" или "Редактировать анонс") в сообщении с фото. Обработчики этих кнопок пытались использовать `query.edit_message_text()`, но сообщение содержало фото, а не просто текст, что вызывало ошибку.

## Решение

Во всех callback-обработчиках, которые могут быть вызваны из сообщения с фото, изменена логика:

### До (неправильно):
```python
await query.edit_message_text("Результат операции")
```

### После (правильно):
```python
# Удаляем старое сообщение (может быть с фото)
try:
    await query.message.delete()
    await context.bot.send_message(
        chat_id=query.message.chat_id,
        text="Результат операции"
    )
except Exception:
    # Если удаление не удалось, пытаемся редактировать
    await query.edit_message_text("Результат операции")
```

## Исправленные функции

В файле [src/list_handlers.py](src/list_handlers.py):

1. ✅ **publish_giveaway** (строки ~430-485)
   - Удаление сообщения перед отправкой результата публикации
   - Улучшенная обработка ошибок

2. ✅ **edit_announcement_step** (строки ~530-600)
   - Удаление сообщения с фото при переходе к редактированию анонса
   - Обработка ошибок при удалении

3. ✅ **reset_announcement** (строки ~675-735)
   - Удаление сообщения при сбросе анонса
   - Улучшенная обработка ошибок

4. ✅ **cancel_edit_announcement** (строки ~740-760)
   - Удаление сообщения при отмене редактирования
   - Fallback на edit если удаление не работает

## Преимущества решения

1. **Универсальность**: работает как с сообщениями с фото, так и с текстовыми
2. **Надёжность**: есть fallback на старый метод если удаление не работает
3. **Консистентность**: одинаковая логика во всех callback-обработчиках
4. **UX**: пользователь видит новое сообщение вместо ошибки
